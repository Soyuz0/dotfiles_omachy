# Selected history and editor additions

These changes were selected from the non-Omarchy dotfiles comparison. No other
editor plugins, shell replacement, window manager, or bootstrap was imported.

## Neovim

The existing leader is Space.

| Mapping | Action |
| --- | --- |
| `<leader>cr` | Copy the file path relative to the current working directory when possible |
| `<leader>a` | Run `LspRestart` |
| `<leader>v` | Run `e!`, reloading the file and discarding unsaved buffer changes |

The relative-path mapping leaves the clipboard unchanged for unnamed buffers.
For a file outside the current working directory, Neovim may retain an absolute
path. The existing `<leader>cp` absolute-path mapping is unchanged.

The reload mapping is deliberately destructive and has no confirmation. It does
not write the discarded changes to disk. Existing Neovim instances are not
reloaded or closed as part of installation. Reopen Neovim when convenient.

## LazyGit

`lazygit/.config/lazygit/config.yml` supplies Nerd Font icons, Tokyo Night colors,
Neovim as the editor, automatic refresh, and automatic fetch while LazyGit runs.
The colors are fixed rather than generated by Omarchy's theme setter. No Git
identity, authentication, repository URLs, or credentials were copied.

The original live empty config is backed up privately; the active file now links
to the repo. The next LazyGit launch reads it. No running LazyGit was restarted.

## Fastfetch

Fastfetch is in `packages/desktop.txt` and runs once per new interactive terminal
through the shared Bash fragment. It uses the existing Fastfetch configuration,
which Omarchy supplies. It does not run in scripts or with redirected output.
Missing or failed Fastfetch does not prevent the shell from starting. Set
`DOTFILES_DISABLE_FASTFETCH=1` in the private Bash overrides to disable the banner.
This machine already has Fastfetch 2.70.0, so no package install was needed.

## Atuin

`atuin/.config/atuin/config.toml` and the Bash fragment provide local command
history. Atuin 18.24.1 includes its Bash preexec integration, so a separate
bash-preexec script is not required for the verified version. It recognizes the
managed `~/.config/atuin/config.toml` when no newer `~/.atuin/config.toml` or explicit
config-directory override takes precedence. Tests verify the managed config is
actually read, rather than merely checking its syntax.

- Ctrl-R opens Atuin search after Omarchy's stock fzf initialization.
- Up-arrow keeps its existing behavior.
- Enter in the search accepts and executes the selected command.
- Cloud auto-sync, sync records, update checks, AI hooks, PTY recording, and the
  daemon are disabled. No account was created or authenticated.
- No old shell history was imported and no live history database was read or copied.
  An isolated synthetic history record confirmed owner-only database permissions
  even with a normal `0022` umask. This version uses `~/.atuin/data` by default.
- Secret filtering is enabled. It recognizes known patterns, not every possible
  secret. Avoid credentials in shell command arguments even with this filter.

Only interactive Bash initializes Atuin, once per shell. The generated init code
uses `--disable-up-arrow --disable-ai`. Private Bash overrides remain in the
ignored `~/.config/bash/local.sh`. To disable Atuin locally, set
`DOTFILES_DISABLE_ATUIN=1` before initialization. No live shell startup file was
sourced during validation.

Open a new terminal for activation. To enable it in an existing interactive
shell, source only the customization fragment when ready:

```bash
source ~/.config/bash/custom.sh
```

Do not restart active commands or source the full live `.bashrc` just to test it.
Atuin will record future commands entered in initialized shells, not commands
that ran before the integration was enabled.

### Installation and updates

Fresh Omarchy installs use `./setup.sh --backup --packages`, which includes the
Arch repository package `atuin` and the managed config root. Without `--packages`,
the config installer does not download the tool; the hook skips a missing binary.

On the implementation machine, sudo required authentication. Atuin was therefore
installed for this user from the official `atuinsh/atuin` GitHub release
`v18.24.1`, not through an unauthenticated root package operation or a pipe-to-shell
installer. The Linux x86_64 GNU archive SHA-256 was checked against both GitHub
release metadata and the companion checksum file:

```text
bd89df077da94e719fd7a6d8e7dbe2f42ca9d4c284e96a1748eae264345c9e81
```

The executable is under `~/.local/share/atuin/releases/18.24.1/atuin`, with a new
`~/.local/bin/atuin` link. Existing local tools and wrappers were not replaced.
The installed binary and its checksum receipt are outside the tracked config.
The existing legacy `~/.local/bin` directory link was not migrated.

This user-local executable does not update itself automatically. Review and
verify a later official release before replacing it, or switch deliberately to
the distribution package when administrative access is available. Do not remove
the active link or binary before its replacement is complete and verified.

## Recovery

The before-update config inventory, original bytes, modes, application receipt,
and live-link operation record are stored privately under:

```text
~/.local/state/dotfiles-omachy/desktop-additions-before-20261115-234420/
```

The `.bashrc` backup may contain private credentials from the original machine.
Never copy it into this repository or publish it. Configuration recovery must
check for changes since this update before restoring an old file. The ordinary
fresh-install `--restore` command only handles installations performed by that
installer; it does not replay this separate, scoped live-update record.
